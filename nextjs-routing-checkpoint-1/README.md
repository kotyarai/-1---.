# Контрольная точка № 1 — Маршрутизация и навигация в Next.js

Учебный проект на Next.js 15+, React и TypeScript с использованием App Router.

## Требования

- Node.js 18.18 или новее (рекомендуется актуальная LTS-версия)
- npm
- Visual Studio Code или другой редактор

## Запуск проекта

1. Распакуйте архив и откройте папку `nextjs-routing-checkpoint-1` в VS Code.
2. Откройте терминал в корне проекта.
3. Установите зависимости:

   ```bash
   npm install
   ```

4. Запустите сервер разработки:

   ```bash
   npm run dev
   ```

5. Откройте http://localhost:3000.

Для проверки production-сборки выполните `npm run build`, а затем `npm start`.

## Реализованные маршруты

| URL | Файл | Назначение |
|---|---|---|
| `/` | `app/page.tsx` | Главная страница |
| `/about` | `app/about/page.tsx` | Статическая страница «О проекте» |
| `/blog` | `app/blog/page.tsx` | Список постов |
| `/blog/1` | `app/blog/[id]/page.tsx` | Динамическая страница поста |
| `/blog/2` | `app/blog/[id]/page.tsx` | Динамическая страница поста |
| `/blog/1/comments/5` | `app/blog/[id]/comments/[commentId]/page.tsx` | Вложенный динамический маршрут комментария |

В проекте есть три поста: `/blog/1`, `/blog/2`, `/blog/3`. Для неизвестного ID поста отображается not-found.

## Где реализованы требования

- **Корневой layout:** `app/layout.tsx` — теги `html` и `body`, общая навигация и футер.
- **Клиентская навигация:** `app/components/NavBar.tsx` — `Link`, `usePathname`, `useRouter`.
- **Статические маршруты:** `app/about/page.tsx`, `app/blog/page.tsx`.
- **Динамический сегмент:** `app/blog/[id]/page.tsx`.
- **Вложенные параметры:** `app/blog/[id]/comments/[commentId]/page.tsx`.
- **Layout раздела:** `app/blog/layout.tsx`.
- **Template раздела:** `app/blog/template.tsx`.
- **Проверка перемонтирования:** `app/blog/TemplateProbe.tsx` выводит сообщения в консоль браузера.

## Как проверить layout и template

1. Откройте `/blog`.
2. Откройте DevTools браузера (F12) и выберите вкладку Console.
3. Перейдите на `/blog/1`, затем `/blog/2`.
4. Найдите сообщения `[Blog template]` о монтировании и размонтировании.
5. Блок «Раздел „Блог“» должен оставаться общей оболочкой для дочерних страниц.

Важно: сообщения от `TemplateProbe` появляются в консоли браузера, потому что логирование находится в клиентском компоненте. Обычный `console.log` в серверном компоненте выводился бы в терминале сервера.

## Контрольные вопросы

1. **Как Next.js определяет URL?**  
   По структуре папок внутри `app/`. Файл `page.tsx` делает соответствующий сегмент доступным как страницу.

2. **Чем отличаются `layout.tsx` и `template.tsx`?**  
   Layout сохраняется между переходами по дочерним маршрутам и может сохранять состояние. Template получает уникальный ключ и перемонтируется при переходах, затрагивающих его сегмент.

3. **Как создать динамический маршрут?**  
   Создать папку с параметром в квадратных скобках, например `app/blog/[id]/page.tsx`.

4. **Почему используют `Link`, а не `<a>`?**  
   `Link` обеспечивает клиентскую навигацию Next.js и позволяет избежать полной перезагрузки документа при внутренних переходах.

5. **Как получить параметры в клиентском компоненте?**  
   С помощью `useParams` из `next/navigation`, например `useParams<{ id: string }>()`.

6. **Что делает `app/blog/layout.tsx`?**  
   Оборачивает все страницы внутри сегмента `/blog`, включая динамические страницы постов и комментариев.

7. **Как создать вложенный динамический маршрут?**  
   Использовать структуру `app/blog/[id]/comments/[commentId]/page.tsx`. Значения доступны как `params.id` и `params.commentId`.

8. **Почему `params` — Promise в Next.js 15+?**  
   В актуальном API параметры маршрута представлены асинхронно. Серверная страница должна ожидать их: `const { id } = await params`.
